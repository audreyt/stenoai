---
title: "How on-device processing works"
description: "Steno keeps audio and transcription on your Mac. Summaries and chat can use a self-hosted loopback model."
---

Steno keeps recorded audio and speech recognition on your Mac. Transcripts and summaries live in the local Steno data directory. Summary and chat prompts go only to the LLM route you configure; this fork's maintained profile uses a self-hosted loopback service.

## The processing pipeline

When you stop a recording, Steno runs this sequence:

```
Audio file (local)
  → Apple SpeechTranscriber, Parakeet, or Whisper (on-device transcription)
  → transcript.txt (saved locally)
  → configured Ollama-compatible service
  → summary.md (saved locally)
```

On macOS 26+, Apple SpeechTranscriber is the default and its locale assets are managed by the operating system. The maintained fork profile sends transcript-derived prompts over loopback to Ornith at `127.0.0.1:11443`. Audio never goes to the LLM service.

## What runs on your Mac

**Transcription: Apple SpeechTranscriber, Parakeet, or Whisper**

Apple SpeechTranscriber is the default on macOS 26+ and provides live and batch transcription through system-managed locale assets. Parakeet remains the live fallback for older macOS versions and Windows. Whisper provides broader post-stop language coverage. All three process audio locally.

**Summary and chat: Ollama-compatible service**

The maintained fork profile uses `ornith-1.5:9b` at `http://127.0.0.1:11443` for summaries and chat during recording. The upstream local-Ollama route on `127.0.0.1:11434`, remote Ollama, cloud, and organisation adapter options remain available.

## What network requests does Steno make?

| Request | When | Why |
|---------|------|-----|
| System speech asset | First use of an Apple locale | macOS installs the selected SpeechTranscriber locale when it is not already present |
| Optional model download | When you choose Parakeet, Whisper, or a bundled Ollama model | Downloads the explicitly selected fallback/model weights |
| Update check | On app launch, then periodically | Checks `github.com/audreyt/stenoai` for fork releases |
| Anonymous usage analytics | On events like recording start/stop, transcription/summarization completion, and errors | Anonymous product-usage telemetry (event names and counts only -- never meeting content); on by default, can be turned off in **Settings → Advanced** |

Audio never leaves the machine. Transcript-derived prompts go to the configured summary/chat endpoint; with the maintained Ornith profile, that traffic stays on loopback. Monitor the process with [Little Snitch](https://www.obdev.at/products/littlesnitch/) or macOS `nettop` if you want to inspect the connection directly.

## Where your data is stored

All data lives in `~/Library/Application Support/stenoai/`:

```
stenoai/
├── recordings/      # .webm audio files
├── transcripts/     # .txt verbatim transcripts
├── output/          # .md summaries and notes
└── models/          # transcription model weights
```

Ollama model weights are stored separately in `~/.ollama/models/` (Ollama's default location).

## Using a cloud model (optional)

Steno optionally supports OpenAI, Anthropic, AWS Bedrock, or a custom API endpoint ("Cloud API" in Settings) as an alternative to the local Ollama model, plus a "Private Server" mode that points at a remote Ollama instance you control. If you configure one of these in **Settings → AI**, your transcript and any notes you've typed for that meeting (not audio) are sent to that provider's API for summarization.

Organizations can also connect Steno to a self-hosted adapter under **Settings → Organisation**, which proxies summarization requests server-side. As with the other cloud options, this sends the transcript (and notes) off-device but never the audio.

Cloud and organization modes are opt-in, off by default, and clearly indicated in the UI. If you work with confidential data, use the local model.

<Accordion title="Does Steno send any telemetry or usage data?">
Yes, anonymous product-usage analytics are on by default -- event names like "recording started" or "summarization completed," plus error types and an anonymous install ID. This never includes audio, transcripts, notes, or summaries. You can turn it off in **Settings → Advanced**. Separately, the only other outbound requests from the app are the update check and model downloads during setup. If you enable a cloud summarization model, transcripts are sent to that provider's API.
</Accordion>

<Accordion title="Can I use Steno in an air-gapped environment?">
Yes, after the initial setup. Download the app and models on a connected machine, then move the installation to your air-gapped environment. All processing runs offline.
</Accordion>

<Accordion title="Is Steno suitable for confidential recordings?">
Steno is designed for professionals handling confidential audio. Because all processing is local and no meeting content (audio, transcript, notes, or summary) leaves your device by default, it is suitable for use cases where sending audio to a cloud service would be inappropriate -- clinical consultations, legal calls, financial briefings. If you need zero network activity at all, turn off anonymous usage analytics in **Settings → Advanced**. Review your organization's specific policies before using any recording tool for regulated data.
</Accordion>

<Accordion title="Where does Ollama run?">
Steno bundles a copy of Ollama and starts it as a local process on `127.0.0.1:11434` when the app launches. It is not accessible from the network. When you quit Steno, Ollama is stopped.
</Accordion>
